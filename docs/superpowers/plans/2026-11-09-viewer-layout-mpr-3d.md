# Viewer Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the 3D view the majority of the Viewer tab by stacking the three MPR planes small in a left column, with an All / 2D / 3D switcher that can collapse either side, and make both option panels float so opening them never displaces a view.

**Architecture:** Confined to `render_viewer_tab()` in `src/visualization/app.py`. A view switcher rendered outside two Streamlit columns, a fixed-height container (or a 2×2 grid in 2D mode) for the MPR planes, and `st.popover` replacing both option expanders. One shared height constant aligns the columns.

**Tech Stack:** Python 3.11, Streamlit 1.37–1.39 (pinned), Plotly 7.1, pytest + `streamlit.testing.v1.AppTest`.

**Spec:** `docs/superpowers/specs/2026-11-09-viewer-layout-design.md` — read §3 (Decisions) alongside this plan. §3.4 holds the measured sizing derivation, §3.5 the switcher, §3.6 the caption move, §3.7 the dependency floor.

## Decisions taken from the mockup

| Aspect | Decision |
|---|---|
| Views | `All` (1:2 split) · `2D` (MPR full width, 2×2 grid) · `3D` (3D full width) |
| Switcher placement | Outside and above the two columns, so it survives a collapse |
| Collapse mechanism | Column ratio `0.0001` → renders at exactly 0 px (verified) |
| Planes in `All` | Vertical stack, images centred |
| Planes in `2D` | 2×2 grid, fourth cell empty |
| Slice/spacing text | Inside Slice Options, not under each image |
| Shared height | `VIEWER_HEIGHT_PX = 700` (was 900; 900 pushed the 3D scene below the fold) |

## Review Focus

1. **Switcher reachability** — the switcher must be rendered outside the two columns. Inside a collapsed column it becomes unreachable and locks the user into that view. Task 2 Step 2 places it before `st.columns`.
2. **Slice clamping ordering** — clamping must precede slice-slider creation, or a resized volume leaves stale keys and raises a widget-key error. Task 2 Step 1.
3. **Image overflow at narrow widths** — `st.image(width=N)` does not shrink. Measured: a 260 px image in a 201 px column overflows and spills into the neighbouring column. Task 2 Step 5 avoids fixed widths.
4. **Plotly does not re-measure on collapse** — when a column widens, Plotly keeps its cached pixel width (observed in the mockup: chart stayed 390 px in a 601 px column). In Streamlit a rerun rebuilds the figure, so this is expected to be fine, but Task 4 Step 4 checks it explicitly.
5. **Anisotropic coronal/sagittal heights** — `to_isotropic` can multiply slice height several-fold. In `All` mode the fixed-height container must scroll instead of stretching the page.
6. **Geometry overlay boundary** — `n_base_traces` must be captured after `create_volume_figure` and before any overlay trace. Pinned by `test_3d_plot_has_a_projection_geometry_toggle_in_the_corner`.
7. **Dependency floor drift** — `pyproject.toml` claims `>=1.28.0` while the app already needs `st.fragment` (1.37.0). Task 1 corrects it; do not revert.

- [ ] **Step 4: Add the constants and helpers**

In `src/visualization/app.py`, above `def render_viewer_tab(`:

```python
# Shared height for the two viewer columns, so the MPR stack and the 3D canvas
# end on one baseline. Both the container and the Plotly figure read this, so
# they cannot drift apart. 700px matches a typical laptop viewport, so the whole
# viewer sits above the fold; a taller canvas pushed the 3D scene out of view.
VIEWER_HEIGHT_PX = 700

# The 3D scene is anchored toward the top of its canvas. Plotly centres a 3D
# scene in its domain, so a centred cube in a tall canvas drops below the fold.
SCENE_DOMAIN_Y = [0.2, 1]

# A column ratio of 0.0001 renders at exactly 0 px, which is how the view
# switcher collapses one side. A literal 0 is rejected by st.columns
# (StreamlitInvalidColumnSpecError: widths must be positive).
COLLAPSED_COLUMN = 0.0001

VIEWER_VIEWS = ("All", "2D", "3D")
VIEWER_COLUMN_SPECS = {
    "All": [1, 2],
    "2D": [1, COLLAPSED_COLUMN],
    "3D": [COLLAPSED_COLUMN, 1],
}


def viewer_column_spec(view: str) -> list[float]:
    """Column widths for a view. Unknown views fall back to the split."""
    return VIEWER_COLUMN_SPECS.get(view, VIEWER_COLUMN_SPECS["All"])


def viewer_has_mpr(view: str) -> bool:
    """3D mode collapses the MPR column entirely."""
    return view != "3D"


def viewer_has_3d(view: str) -> bool:
    """2D mode collapses the 3D column entirely."""
    return view != "2D"
```

Move the existing body in unchanged (Display Unit, attenuation-only energy slider, Preset, Center/Width, three slice sliders). Then, after the slice sliders, append the per-plane readout that used to sit under each image:

```python
st.divider()
for label, maximum, (_, spacing, index) in (
    ("Axial", axial_max, raw_slices["axial"]),
    ("Coronal", coronal_max, raw_slices["coronal"]),
    ("Sagittal", sagittal_max, raw_slices["sagittal"]),
):
    st.caption(
        f"**{label}** — slice {index + 1}/{maximum + 1} | "
        f"spacing ({spacing[0]:.4f}, {spacing[1]:.4f}) mm"
    )
```

The spacing is needed inside the popover but the images are built after it, so
extract every slice once *before* the popover and reuse the array for the image.
Do not call `extract_slice` twice per plane:

```python
raw_slices = {}
for plane in ("axial", "coronal", "sagittal"):
    index = st.session_state[f"{plane}_slice"]
    raw, plane_spacing = extract_slice(volume, plane, index)
    raw_slices[plane] = (raw, plane_spacing, index)
```

- [ ] **Step 5: Render the MPR planes, stacked or as a 2×2 grid**

Still inside `with col_mpr:`, after the popover, window the slices and render
them. `use_column_width=True` is used unchanged — a fixed pixel width overflows
a narrow column (verified: 260 px image in a 201 px column spills into the
neighbour).

```python
images = {}
for plane, (raw, plane_spacing, index) in raw_slices.items():
    display = to_display_units(raw, display_unit, energy_kev)
    windowed = apply_window(display, center, width)
    if plane != "axial":
        windowed = to_isotropic(windowed, plane_spacing)  # correct aspect ratio
    images[plane] = windowed

if viewer_has_mpr(view):
    if view == "2D":
        row1 = st.columns(2)
        row2 = st.columns(2)
        targets = [row1[0], row1[1], row2[0]]
    else:
        container = st.container(height=VIEWER_HEIGHT_PX, border=False)
        targets = [container] * 3

    for name, plane, target in zip(
        ("Axial", "Coronal", "Sagittal"),
        ("axial", "coronal", "sagittal"),
        targets,
    ):
        with target:
            st.markdown(f"**{name}**")
            st.image(images[plane], clamp=True, use_column_width=True)
```

Window settings live inside the popover, so the windowing must happen *after*
the popover body has run. Do not try to read `display_unit` before that.

`border=False` is deliberate: the default `border=True` frames the stack (spec
§3.3). The per-plane `st.caption` is gone — it lives in the popover.
